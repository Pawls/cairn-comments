### ~~A1 — Python round trip: CLI + git filter~~ · Fable 5.1 / high — SHIPPED 2026-09-21 {#a1}

**Status:** Shipped on branch `v1`. 57 tests pass on Windows (git 2.55, Node 24) and in
WSL Ubuntu (git 2.43, Node 26); the integration scenarios run under both `autocrlf`
settings on each. Rules settled along the way, and the one-shot latency (80 ms with one
marker, so the kill criterion did not fire), are in design.md § Rules settled in A1.

Visible change: in a repo after `init`, an agent worktree shows full `#~` comments, the
owner's checkout and every blob show bare markers, and bodies are tracked under
`.agents/comments/`.

- [x] npm workspaces scaffold: `packages/core`, `packages/cli`, `packages/vscode` (empty
      shell), TypeScript, vitest, eslint; brand name held in one constant in `core`
      (`packages/cli/test/brand.test.ts` guards the one copy `package.json` must repeat).
- [x] `core`: marker grammar (new, expanded, bare; own-line, trailing, multi-line block)
      parsed from tree-sitter comment nodes for Python, so sigils inside strings are
      ignored. Unit tests cover each form plus the string false positive.
- [x] `core`: pure `clean` with deterministic ids for new comments; property test that
      `clean(clean(x)) == clean(x)` and `clean(smudge(clean(x))) == clean(x)`. The second
      property found a real bug: one id on an own-line and a trailing marker.
- [x] `core`: sidecar markdown reader/writer with a reserved per-entry metadata line
      (filled by A6 and A7); stable output ordering so rewrites produce minimal diffs.
- [x] `core`: every rewrite preserves each line's terminator; tests run fixtures in LF,
      CRLF, and mixed.
- [x] `cli`: `clean`, `smudge`, `sync`, `expand`, `collapse` commands. `sync`, `expand`,
      and `collapse` finish with the guarded `git update-index` re-stat (design.md,
      spike finding 5). Disabling the re-stat fails 8 integration tests with finding 5's
      modified-but-empty-diff symptom.
- [x] `cli init`: writes `.gitattributes` entries (sources plus `merge=union` for the
      sidecar folder), filter config, `extensions.worktreeConfig`, and a pre-commit hook
      installed into the effective hooks dir, chaining any existing hook (finding 4).
- [x] `cli worktree add`: `--no-checkout`, enable smudge with `git config --worktree`,
      then check out.
- [x] Integration test ports every spike scenario to a temp repo: diff shows bare markers
      only, `commit -am` carries the sidecar, merge to owner checkout stays collapsed,
      fresh smudged worktree expands, branch switch, cherry-pick, size-changing body edit
      ends `git status` clean after `sync`.
- [x] Integration test with a global-style `core.hooksPath` set.
- [x] Delete `spikes/git-filter-roundtrip/` once the integration test covers it.

Verify: `npm test` (unit + integration) on Windows and in WSL or CI Linux.
Kill criteria: if tree-sitter WASM startup makes a one-shot `clean` slower than 300 ms per
file, move A4 ahead of A2 rather than optimizing the one-shot path.

### ~~A4 — Long-running filter process and perf budget~~ · Opus 5 / medium — SHIPPED 2026-09-22 {#a4}

**Status:** Shipped on branch `v1`. 117 tests pass on Windows (git 2.55, Node 24) and in
WSL Ubuntu (git 2.43, Node 26); lint clean. The checkout budget failed, so the kill
criterion was invoked: numbers and the native-binary / worker-thread note are in
design.md § Filter process and § Known gaps.

Visible change: a 2,000-file checkout into an agent worktree takes 1.8 s instead of
220 s (Windows); warm `git status` costs nothing extra.

- [x] Implement git's long-running filter process protocol (`filter.<name>.process`),
      keeping parsers warm across files; one-shot commands remain as fallback
      (`init --one-shot`). Smudges use git's `delay` capability so sidecar reads overlap
      git's own writes.
- [x] Benchmark script (`scripts/bench.ts`, `npm run bench`): generated repo with 2,000
      marked source files; checkout and `git status` times with the filter off, one-shot,
      and process mode.
- [x] Budget: warm `git status` passes (+0 ms). Checkout fails: +89% on Windows (947 →
      1,788 ms, down from +201% before delay), +378% on Linux (138 → 657 ms). Results
      recorded in design.md.
- [x] Protocol conformance tests, including a filter crash mid-stream: git names the
      failed filter, no file or index entry is ever a fragment, and rerunning the
      checkout recovers.

Verify: `npm run bench`, `npm test`. Kill criteria invoked: Node misses the checkout
budget; recorded, design note opened, v1 not blocked.

- [x] Heuristic detectors, each with a name and score: restates the next line, narrates

- [x] Protected classes are never candidates: doc comments, pragmas, suppression
      directives, license headers, ticketed TODOs, commented-out code (plus
      `unconvertible` inline and JSX block comments). 42 protected corpus cases assert
      their class.
- [x] `scan --json`, `scan --apply` (from a reviewed list), and `scan --mark-all`
      (`packages/cli/test/scan.test.ts`, both `autocrlf` settings).
- [x] VS Code review tree: grouped by file, accept/reject per comment or per file, apply
      button; rejected comments are remembered in `.agents/scan-ignore` so repeats stay
      quiet (`packages/vscode/e2e/review.test.ts`; tree rendering checked by screenshot).
- [x] Applying runs `sync` (and `collapse` outside agent worktrees) and leaves `git
      status` showing only the marker edits, sidecars, and ignore file.

review-flow check. Kill criteria invoked: restates-code (0.68) and filler-opener (0.39)

### ~~A7 — Staleness flags~~ · Fable 5.1 / medium — SHIPPED 2026-09-22 {#a7}

**Status:** Shipped on branch `v1`. 231 tests pass on Windows (git 2.55, Node 24) and in
WSL Ubuntu (git 2.43, Node 26); 12 e2e tests pass in VS Code 1.138; lint clean. The kill criterion did not
fire: 16 formatter-only pairs across the five languages hash equal, and 11 real changes
do not. Rules and the benchmark are in design.md § Staleness.

Visible change: when anchored code changes and its comment does not, the overlay marks
the comment possibly stale and smudged text carries a `[stale?]` tag.

- [x] `sync` stores a normalized hash of the anchored code in the entry metadata line
      (`anchor=`). "Next sibling node" did not hold: tree-sitter-python attaches a comment
      above a block's first statement to the enclosing `def`. The anchor is found by
      position instead (the node starting the next code line at the marker's indent), and
      a declaration contributes its signature, not its body.
- [x] Stale when the current hash differs from the stored one and the body is unchanged;
      editing the body or running `confirm <id>` clears it
      (`packages/core/test/stale.test.ts`).
- [x] Overlay badge (`~?` off, `[stale?]` on, warning color), a hover with **Confirm: still
      accurate**, and `Slopstash: Review Stale AI Comments`; `check --stale` exits 1 for CI
      (`packages/cli/test/stale.test.ts`, both `autocrlf`).
- [x] `clean` strips the `[stale?]` tag so it never reaches a blob or the sidecar: every
      reader drops it through `findMarkers`, and `smudge`/`expand` add or remove it in place.

Verify: `npm test`. Kill criteria: whitespace-only or formatter-only changes flagging
stale means the normalization is wrong; fix before shipping, do not ship noisy.

### ~~A8 — Promote and demote~~ · Sonnet 5 / medium — SHIPPED 2026-09-22 {#a8}

**Status:** Shipped on branch `v1`. 253 tests pass on Windows and in WSL Ubuntu; 13 e2e
tests pass in VS Code 1.138; lint clean. Rules are in design.md § Promote and demote.

Visible change: one action turns an AI comment into a normal committed comment, and the
reverse moves any comment into the sidecar.

- [x] `promote <id>`: replace the marker with the body as a plain comment, remove the
      sidecar entry. `demote <file>:<line>`: add the sigil and `sync`. Demote refuses doc,
      pragma, license, and unconvertible comments ("any comment" held only for the rest),
      and an emptied sidecar is deleted.
- [x] VS Code code actions on markers and on ordinary comments (they run the CLI).
- [x] Round-trip test: demote then promote restores the original bytes
      (`packages/core/test/promote.test.ts` per language, `packages/cli/test/promote.test.ts`
      through git under both `autocrlf`, and the review e2e suite). Exact for
      `<prefix> text` line comments; a block comment comes back as line comments.

Verify: `npm test`. Kill criteria: none.
