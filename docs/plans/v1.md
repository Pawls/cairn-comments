### A1 — Python round trip: CLI + git filter · Fable 5.1 / high {#a1}

**Status:** Not started. The spike proves the mechanism with regexes and a one-shot
filter; this slice replaces it with a tree-sitter core, a real CLI, and integration tests.

Visible change: in a repo after `init`, an agent worktree shows full `#~` comments, the
owner's checkout and every blob show bare markers, and bodies are tracked under
`.agents/comments/`.

- [ ] npm workspaces scaffold: `packages/core`, `packages/cli`, `packages/vscode` (empty
      shell), TypeScript, vitest, eslint; brand name held in one constant in `core`.
- [ ] `core`: marker grammar (new, expanded, bare; own-line, trailing, multi-line block)
      parsed from tree-sitter comment nodes for Python, so sigils inside strings are
      ignored. Unit tests cover each form plus the string false positive.
- [ ] `core`: pure `clean` with deterministic ids for new comments; property test that
      `clean(clean(x)) == clean(x)` and `clean(smudge(clean(x))) == clean(x)`.
- [ ] `core`: sidecar markdown reader/writer with a reserved per-entry metadata line
      (filled by A6 and A7); stable output ordering so rewrites produce minimal diffs.
- [ ] `core`: every rewrite preserves each line's terminator; tests run fixtures in LF,
      CRLF, and mixed.
- [ ] `cli`: `clean`, `smudge`, `sync`, `expand`, `collapse` commands. `sync`, `expand`,
      and `collapse` finish with the guarded `git update-index` re-stat (design.md,
      spike finding 5).
- [ ] `cli init`: writes `.gitattributes` entries (sources plus `merge=union` for the
      sidecar folder), filter config, `extensions.worktreeConfig`, and a pre-commit hook
      installed into the effective hooks dir, chaining any existing hook (finding 4).
- [ ] `cli worktree add`: `--no-checkout`, enable smudge with `git config --worktree`,
      then check out.
- [ ] Integration test ports every spike scenario to a temp repo: diff shows bare markers
      only, `commit -am` carries the sidecar, merge to owner checkout stays collapsed,
      fresh smudged worktree expands, branch switch, cherry-pick, size-changing body edit
      ends `git status` clean after `sync`.
- [ ] Integration test with a global-style `core.hooksPath` set.
- [ ] Delete `spikes/git-filter-roundtrip/` once the integration test covers it.

Verify: `npm test` (unit + integration) on Windows and in WSL or CI Linux.
Kill criteria: if tree-sitter WASM startup makes a one-shot `clean` slower than 300 ms per
file, move A4 ahead of A2 rather than optimizing the one-shot path.

Verify: `npm run test:vscode`; manual check in an Extension Development Host.
Kill criteria: none; the CodeLens fallback bounds the risk.

### A4 — Long-running filter process and perf budget · Opus 5 / medium {#a4}

**Status:** Not started.

Visible change: checkouts in large repos are not noticeably slower with the filter on.

- [ ] Implement git's long-running filter process protocol (`filter.<name>.process`),
      keeping parsers warm across files; one-shot commands remain as fallback.
- [ ] Benchmark script: generated repo with 2,000 marked source files; record checkout
      and `git status` times with the filter off, one-shot, and process mode.
- [ ] Budget: process mode adds under 20% to a full checkout and under 1 s to a warm
      `git status`. Results recorded in design.md.
- [ ] Protocol conformance tests, including a filter crash mid-stream leaving git with a
      clear error and no corrupted files.

Verify: `npm run bench`, `npm test`. Kill criteria: if Node cannot meet the budget,
record the numbers and open a design note on a native filter binary; do not block v1.

### A5 — Scan: detect existing AI comments · Fable 5.1 / high {#a5}

**Status:** Not started.

Visible change: `scan` on an existing repo lists likely AI comments; the user reviews
them in VS Code and converts the accepted ones to sigil comments in one step. Repeatable.

- [ ] Heuristic detectors, each with a name and score: restates the next line, narrates
      steps, change-history phrasing ("Updated to", "Fixed", "NEW:"), emoji, filler
      openers, hedging boilerplate. Labeled fixture corpus with precision reported per
      detector.
- [ ] Protected classes are never candidates: doc comments, pragmas, suppression
      directives, license headers, ticketed TODOs, commented-out code.
- [ ] `scan --json`, `scan --apply` (from a reviewed list), and `scan --mark-all`.
- [ ] VS Code review tree: grouped by file, accept/reject per comment or per file, apply
      button; rejected comments are remembered in a tracked ignore file so repeats stay
      quiet.
- [ ] Applying runs `sync` and leaves `git status` showing only intended changes.

Verify: `npm test` including corpus precision thresholds; manual review-flow check.
Kill criteria: a detector under 80% precision on the corpus ships disabled by default.

### A6 — Hook adapters and provenance · Opus 5 / medium {#a6}

**Status:** Not started.

Visible change: comments an agent writes without the sigil get tagged automatically, and
each sidecar entry records who wrote it.

- [ ] `tag --changed`: diff comment nodes against the index, add the sigil to new
      unprotected comments, run `sync`. This is the generic post-edit command.
- [ ] Claude Code adapter: PostToolUse on Edit/Write calls `tag` for the touched file and
      records session id, model, and timestamp in the entry metadata line.
- [ ] Codex CLI adapter and Cursor adapter, each using the narrowest hook surface that
      harness offers; document what each can and cannot capture.
- [ ] `init --hooks <harness>` installs adapters; AGENTS.md snippet generator for the
      sigil convention.
- [ ] Overlay hover shows provenance.

Verify: `npm test` with recorded hook payload fixtures per harness; one live run per
harness recorded in the PR. Kill criteria: a harness without a usable hook surface gets
the generic command documented instead of an adapter.

### A7 — Staleness flags · Fable 5.1 / medium {#a7}

**Status:** Not started.

Visible change: when anchored code changes and its comment does not, the overlay marks
the comment possibly stale and smudged text carries a `[stale?]` tag.

- [ ] `sync` stores a normalized hash of the anchored statement (next sibling node for
      own-line, same-line node for trailing) in the entry metadata line.
- [ ] Stale when the current hash differs from the stored one and the body is unchanged;
      editing the body or running `confirm <id>` clears it.
- [ ] Overlay badge plus a "Review stale comments" list; `check --stale` exit code for CI.
- [ ] `clean` strips the `[stale?]` tag so it never reaches a blob or the sidecar.

Verify: `npm test`. Kill criteria: whitespace-only or formatter-only changes flagging
stale means the normalization is wrong; fix before shipping, do not ship noisy.

### A8 — Promote and demote · Sonnet 5 / medium {#a8}

**Status:** Not started.

Visible change: one action turns an AI comment into a normal committed comment, and the
reverse moves any comment into the sidecar.

- [ ] `promote <id>`: replace the marker with the body as a plain comment, remove the

- [ ] VS Code code actions on markers and on ordinary comments.
- [ ] Round-trip test: demote then promote restores the original bytes.

Verify: `npm test`. Kill criteria: none.

### A9 — Guard, installer polish, and publish · Opus 5 / medium {#a9}

**Status:** Not started. Blocked on the final name decision (design.md § Naming).

Visible change: the tool is installable by strangers and safe in repos where some clones
lack the filter.

- [ ] `check`: fails on expanded sigil comments in blobs, markers without bodies, and
      bodies without markers; `check --fix` relocates sidecars after renames by id.
- [ ] GitHub Action wrapping `check`; pre-commit hook runs it too.
- [ ] `init` is idempotent, has `--dry-run` and `uninstall`, and prints exactly what it
      changed.
- [ ] Revisit `merge=union` for sidecars with a scripted concurrent-edit scenario;
      replace with a merge driver if bodies get mangled.
- [ ] CI matrix: Windows, macOS, Linux; Node LTS versions.
- [ ] Final name chosen by the owner and applied through the single constant; npm and
      Marketplace names reserved.
- [ ] README with screenshots, quickstart, agent setup per harness, FAQ (token cost,
      what stays in the repo, how to remove the tool).
- [ ] Publish to npm and the Marketplace.

Verify: CI green on all platforms; install from the published packages into a clean
machine or container and run the quickstart. Kill criteria: none.
